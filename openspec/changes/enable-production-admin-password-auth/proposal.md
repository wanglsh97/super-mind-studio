## Why

管理员后台已经部署到公网，但现有认证只接受固定开发凭据 `root/123456`，并由生产环境启动校验强制关闭。
用户已明确要求开放线上管理员登录，因此必须先替换可猜测的固定密码，不能通过移除安全门槛直接暴露开发账号。

## What Changes

- 保留开发环境可选的固定凭据，新增独立的生产管理员密码认证开关。
- 生产管理员用户名和 `scrypt` 密码哈希由 ECS 环境变量注入；应用不接收或保存明文生产密码。
- 生产启动时校验开关、用户名和哈希必须完整，继续禁止固定 `root/123456` 开关。
- 管理员 Session 继续使用短期签名 Secure/HttpOnly/SameSite=Strict Cookie，登录继续受独立 IP 限流保护。
- 部署时生成一次性强密码，只向运维者交付一次；服务器仅写入哈希。

## Capabilities

### Modified Capabilities

- `admin-console`: 增加生产可用的环境哈希密码认证，同时保留开发固定凭据作为显式开发模式。

## Impact

- API 管理员认证 Service、环境校验、单元测试和 Compose 环境白名单。
- Web 登录成功后展示运行时管理员用户名，不再假设 Session 用户一定是 `root`。
- `.env` 示例、生产环境模板和 ECS 部署手册。
- 不修改数据库结构，不建立管理员用户表或 RBAC。

## Non-goals

- 多管理员、RBAC、密码找回、MFA、第三方管理员 OAuth 或后台自助修改密码。
- 将普通 UserSession 与管理员 Session 合并。
- 在仓库、镜像、日志或数据库中保存生产明文密码。

## Acceptance and Rollback Boundary

验收要求生产配置只能使用合法 `scrypt-v1` 哈希启动，正确密码登录后获得短期管理员 Session，错误密码返回
统一 401，固定开发凭据在生产仍被拒绝。回滚只需关闭生产管理员登录开关并重新部署，不涉及数据库恢复。
