## 一、项目背景

当前大模型生态呈现"多极共存"局面，通义千问、智谱GLM、DeepSeek 等国产模型能力各有所长。开发者和用户在接入使用时，面临以下痛点：

1. **接入碎片化**：每家模型有独立的 SDK、鉴权方式和计费规则，切换成本高。
2. **复杂任务难以持续**：一次性对话缺少持久会话、工具调用和可恢复执行状态。
3. **成本失控风险**：流式调用中 Token 消耗不可见，容易超支。
4. **能力分散**：Chat、文生图、Prompt 优化等能力分散在不同平台，需多端切换。

本项目的核心价值是打造一个面向灵感探索与内容创作的 **AI Creative Workspace**：通过自研网关屏蔽底层差异，上层提供开箱即用的 AI 工具集，同时作为全栈技术能力的完整展示。`Super Mind Studio` 是产品品牌，AI Gateway 是承载统一协议、路由、计费和治理的底层技术模块。

## 二、项目目标

### 2.1 业务目标
- 提供一个**可公开访问的用户前台**，让登录用户通过 Agent 体验普通对话、多步任务和 Skill
- 提供一个**仅管理员可访问的中后台**，用于查看监控指标、请求日志和管理业务数据表
- 作为**技术作品集核心项目**，在求职面试中完整展示全栈架构、AI 工程化和产品交付能力

### 2.2 技术目标
- 构建**自研 AI 网关**，统一接入 ≥3 家国内合规大模型
- 封装单一 **AI SDK 包 `@supermind/sdk`**，将多模型调用复杂度从应用层剥离；V1 作为 Monorepo 内部包使用，npm 公开发布后置
- 实现 **Web 用户工作台**：统一 Agent 对话入口和 Skill 市场；Image/Prompt 作为底层网关与 SDK 能力保留
- 实现 **可观测性与运营后台**：Token 计费、调用监控、健康检查、日志查询和业务表管理

## 三、项目范围

### 3.1 In Scope（包含，MVP必须）

| 模块 | 说明 |
|------|------|
| **网关层** | 统一接入通义千问（Qwen）、智谱 GLM、DeepSeek；支持流式 SSE 输出 |
| **智能路由** | 支持手动选模型；支持故障自动切换（failover） |
| **限流熔断** | 基于 IP 的限流（Chat 10 次/分钟、文生图 5 次/分钟），单次 max_tokens 上限 4096 |
| **计费系统** | 实时累加 Token 消耗，展示单次调用成本（按官方定价换算为人民币） |
| **Agent 对话** | 根路径 `/` 统一承载普通对话、持久会话和工具型多步任务；登录成功后直接进入 |
| **文生图** | 保留 `mock-image` 提交任务、轮询、持久化与代理下载闭环，不接入真实图片 Provider |
| **Prompt 优化** | 输入原始 Prompt，AI 返回优化版本（扩写、精简、结构化） |
| **用户前台** | 支持一次性匿名、GitHub OAuth、Google OAuth 登录后提供统一 Agent 和 Skill 市场；不提供独立 Chat/Compare/Image/Prompt 页面，响应式设计并支持亮/暗色主题 |
| **用户身份** | 通用 User 模型、三种互不合并的身份来源、30 天固定有效期的服务端数据库 Session、请求日志用户归属和图片任务所有权 |
| **管理后台** | 面向单一管理员，提供登录、Dashboard、请求日志和数据库业务表查看/修改/删除 |
| **SDK 封装** | 在 `packages/sdk` 中维护单一包 `@supermind/sdk`，提供 Agent、Image、Prompt 与 Skill 市场能力；普通模型调用仅作为服务端内部端口，Web 通过 `workspace:*` 引用 |
| **部署上线** | Docker Compose 一键启动；Next.js、NestJS、PostgreSQL、Redis 与 Nginx 统一以容器方式部署在同一台阿里云 ECS，支持公网 IP 与域名访问 |
| **监控看板** | 作为管理后台页面，展示今日调用量、Token 消耗趋势、各模型响应延迟与最近错误 |

| **多模型对比** | 不提供 `/chat/compare` 页面、对比入口、SDK compare helper 或公开 Chat completions API |
| **营销首页与 Agent 别名** | 不维护 Hero 营销首页或 `/agent` 页面；根路径直接渲染登录保护的 Agent，`/agent` 不做兼容跳转 |
| **独立 Image/Prompt 页面** | 不提供 `/image`、`/prompt` C 端路由且不做兼容跳转；底层 API、SDK、数据和管理能力继续保留 |
| **C 端 API 展示页** | 不提供手工维护的 `/api` 页面；同源 `/api/v1/*` 网关、Swagger、SDK 与仓库开发文档继续保留 |
| **微服务拆分** | V1 不拆分为独立微服务；Web 与网关在同一台 ECS 上以独立容器运行，代码仓库统一采用 Monorepo 管理 |

| **付费充值** | 不涉及用户充值、余额扣费；项目自费承担演示额度，V1 开发测试期间人工控制调用量，自动日预算保护后续实现 |
| **移动端 App** | 仅 Web 端，不做 React Native / Flutter |

## 五、功能需求详情

### 5.1 模块一：AI 网关（核心底层）

| 功能点 | 优先级 | 说明 |
|--------|--------|------|
| 多模型统一接入 | P0 | 支持 Qwen、GLM、DeepSeek、Kimi 四家官方 API，由 Agent 内部模型调用端口统一 reasoning/text/tool/usage/finish 事件；不提供公开 Chat completions 产品接口 |
| 流式协议转换 | P0 | 将各厂商 SSE 规范化为 Agent 可恢复事件流，thinking 单独映射为 reasoning 事件 |
| 模型健康检查 | P1 | 以真实请求的成功率/延迟为主的**被动健康检查**；辅以每 60s 一次的轻量探测（调用 models 列表等低成本端点，不占用对话额度），维护 `healthy` 状态 |
| 智能故障转移 | P1 | Agent 单次模型调用在首个 reasoning/text/tool 事件前遇到合格 5xx/超时时最多切换一次；首事件后禁止切换 |
| 请求取消 | P1 | **尽力而为**：前端取消时通过 AbortController 传递信号到网关，网关断开与模型的连接并停止向前端推送；不保证模型侧立即停止计算与计费 |
| 实时 Token 计费 | P2 | 流结束时统计 prompt_tokens + completion_tokens，按官方定价换算为人民币并返回前端展示；**文生图按厂商「张数 × 单价」计费，不使用 Token 口径** |
| 统一日志 | P1 | 每次调用记录：requestId、model、prompt、tokens、耗时、成功/失败状态，结构化存储（Pino JSON 格式） |

### 5.2 模块二：AI SDK（单包）

> **包名与目录**：npm 包名统一为 `@supermind/sdk`，源码位于 `packages/sdk`。V1 作为 pnpm workspace 内部包供 Web 使用，不要求发布到 npm；后续确认 npm scope 权限后再公开发布。
>
> **存在价值（差异化说明）**：SDK 封装持久 Agent thread/run/event、断线补读、Skill/MCP、文生图「提交 + 轮询」、Prompt 优化和人民币费用解析。Web 前端强制通过本 SDK 调用网关。

| 功能点 | 优先级 | 说明 |
|--------|--------|------|
| 单包结构 | P0 | 仅维护 `@supermind/sdk` 一个包，不将 Chat、Image、Prompt 拆成多个 npm 包 |
| 统一调用接口 | P0 | `client.agent.*`、`client.images.*`、`client.prompts.optimize()` |
| TypeScript 类型导出 | P0 | 包含完整的 Request/Response 类型定义，IDE 自动补全 |
| 浏览器 + Node 双端兼容 | P1 | 打包为 CJS + ESM 双格式，`tsup` 构建 |
| 内置重试与超时 | P2 | 自动重试一次（可配置），默认超时 60s |

### 5.3 模块三：Web 应用功能

Web 应用分为用户前台与管理后台。统一 `/login` 页面公开；根路径 `/` 直接渲染登录保护的 Agent，登录成功后返回 `/`。C 端不注册 `/agent`、`/image`、`/prompt` 路由，也不提供兼容跳转；对应 Image/Prompt API、SDK、数据记录与管理端能力继续保留。管理后台位于 `/admin`，使用独立管理员认证。

#### 5.3.1 Agent 对话

| 功能点 | 说明 |
|--------|------|
| 统一入口 | `/` 是普通对话与多步工具任务的唯一主入口；访问旧 `/chat` 自动跳转到 `/`，`/agent` 直接返回 404 |
| 单模型对话 | 选择 Agent-capable 模型，在持久 thread 中流式输出；不需要工具时可直接回答 |
| 对话历史 | Agent 会话持久化到 PostgreSQL，支持刷新恢复、新建、重命名和删除 |
| 停止生成 | Agent run 提供停止能力；已生成内容保留展示 |
| 异常态表现 | 触发 429 时提示"请求过于频繁，请稍后重试"并禁用发送按钮至冷却结束；模型不可用时提示"服务暂时不可用" |

#### 5.3.2 文生图（Image Generation）

V1 保留 Image 网关接口、Provider Adapter、SDK 封装、任务持久化、下载代理和管理端日志，不再提供独立 C 端页面。`/image` 无路由并直接返回 404；已有 localStorage 历史键不主动清理。

#### 5.3.3 Prompt 优化（Prompt Optimizer）

V1 保留 Prompt 优化 API、三种服务端模板、SDK 封装、计费和日志，不再提供独立 C 端页面。`/prompt` 无路由并直接返回 404，后续可由 Agent 工具或内部场景复用该能力。

#### 5.3.3A 通用 Agent 与 Skill 市场

| 功能点 | 说明 |
|--------|------|
| 持久 Agent | 服务端执行多轮模型与工具循环，会话、事件和运行结果可刷新恢复 |
| Skill 市场 | 展示平台审核的 Skill，并支持用户安装、启用、停用和卸载 |
| Skill 加载 | 每次模型调用前按当前用户加载已安装且启用的 Skill，并记录精确版本 manifest |
| 安全边界 | Skill 仅提供工作方法，不执行代码、不读取凭证、不扫描目录，也不能增加工具权限 |

#### 5.3.4 管理后台监控仪表盘（Admin Dashboard）

| 功能点 | 说明 |
|--------|------|
| 今日概览 | **全站（所有登录用户聚合）** 总调用次数、总 Token 消耗、预估总费用（元） |
| 模型响应延迟 | 各模型近 1 小时延迟柱状图（ECharts）；展示 **p95/均值 + 样本数**，低样本量下不展示 p99 以免失真 |
| 调用趋势 | 近 24 小时调用量折线图（按小时聚合） |
| 最近错误 | 展示最近 10 条失败记录（含错误原因） |

#### 5.3.5 请求日志管理

| 功能点 | 说明 |
|--------|------|
| 日志列表 | 分页展示 requestId、通用用户摘要、功能类型、请求模型、实际模型、状态、Token、费用、TTFB、总耗时和请求时间 |
| 筛选排序 | 支持按 requestId、登录来源、用户名称、Provider ID、功能类型、模型、状态和时间范围筛选，并按时间、费用或耗时排序 |
| 日志详情 | 展示完整 Prompt、通用用户身份、模型返回元数据、failover 信息和完整错误信息 |
| 修改记录 | 仅允许修改后台定义的可编辑字段；主键、requestId、关联键和创建时间不可修改 |
| 删除记录 | 删除前二次确认；有关联计费记录时由后端事务统一处理 |

#### 5.3.6 数据库业务表管理

| 功能点 | 说明 |
|--------|------|
| 表清单 | 仅展示白名单业务表：调用日志、计费明细、文生图任务和管理员操作审计 |
| 数据浏览 | 支持分页、筛选、排序、列显示控制和单条详情查看 |
| 数据修改 | 根据每张表的字段白名单校验并修改记录，禁止任意字段透传 |
| 数据删除 | 支持删除允许删除的记录；审计记录只读，不允许通过后台修改或删除 |
| 操作审计 | 管理员修改、删除操作记录操作者、表名、记录 ID、变更前后内容和时间 |
| 明确边界 | 不提供任意 SQL 执行、数据库结构修改、迁移管理或系统表访问 |

### 5.4 模块四：数据存储

| 数据实体 | 存储方式 | 说明 |
|----------|---------|------|
| 调用日志 | PostgreSQL（prisma.logs） | 记录每次请求的完整元数据，用于 Dashboard 展示 |
| 计费明细 | PostgreSQL（prisma.billing） | 记录每次调用的费用明细，关联 requestId |
| 文生图任务 | PostgreSQL（prisma.imageTasks） | 保存平台任务与厂商任务 ID、状态和结果 URL |
| 管理员操作审计 | PostgreSQL（prisma.adminAuditLogs） | 保存管理员对业务数据的修改和删除记录，只读不可删改 |
| 模型健康状态 | Redis（Hash） | 实时更新各模型状态（healthy/unhealthy/latency） |
| 限流计数器 | Redis（String + TTL） | 按 IP 记录每分钟调用次数，TTL 60s 自动过期 |

> V1 暂不引入消息队列或独立 Worker。调用结束后由 NestJS 直接将调用日志与计费明细写入 PostgreSQL；异步队列在出现明确的削峰、重试或后台任务需求后再引入。
>
> V1 为简化开发与问题排查，PostgreSQL 调用日志和 Pino 结构化日志均保留完整 Prompt，暂不实现脱敏和自动清理。完整 Prompt 仅在登录后的管理后台请求详情中展示，用户前台和 Dashboard 聚合接口不返回 Prompt。相关数据治理能力列入后续待办。

> 平台 API 使用稳定模型别名，不把厂商随时可能调整或下线的 model id 暴露为长期接口契约。实际厂商模型 ID 与定价在配置中集中维护；下表为占位示例，开发时以官方实际信息填充。

| 类型 | 平台 model 别名 | 厂商 | 实际模型配置 | 计费口径 | 单价（占位，以官方为准） |
|------|------------------|------|--------------|----------|------------------------|
| Chat | `qwen` | 通义千问 | `QWEN_CHAT_MODEL` | 输入/输出 Token 分别计价 | ¥x / 百万 Token |
| Chat | `glm` | 智谱 GLM | `GLM_CHAT_MODEL` | 输入/输出 Token 分别计价 | ¥x / 百万 Token |
| Chat | `deepseek` | DeepSeek | `DEEPSEEK_CHAT_MODEL` | 输入/输出 Token 分别计价 | ¥x / 百万 Token |

## 六、非功能需求（NFR）

| 分类 | 具体要求 |
|------|---------|
| **性能** | 网关首字节响应（TTFB）≤ 500ms（不含模型侧延迟）；SSE 流式输出无卡顿 |
| **可用性** | 单个模型故障时，系统自动切换备用模型，用户无感知（降级可用率 ≥ 99%） |
| **安全** | 所有 API Key 仅存于服务端 `.env`；管理后台和管理 API 必须经过固定管理员登录会话校验，用户前台不能访问日志、数据库管理接口和敏感信息。默认弱密码仅限开发联调，正式公开前必须替换 |
| **限流** | 单 IP 每分钟最多 10 次 Chat 调用 + 5 次文生图调用，超限返回 429 |
| **成本控制** | V1 仅记录 Token 消耗与预估费用，优先跑通核心业务流程；全站预算硬顶、异常流量防刷和演示额度保护延后实现 |
| **可维护性** | 代码 ESLint + Prettier 强制规范；GitHub Actions 自动跑 CI（build + lint + 关键路径测试） |
| **可测试性** | 对网关核心路径（协议转换、限流、failover、计费换算）提供单元测试；至少 1 条覆盖 Chat 流式的端到端冒烟测试 |
| **配置管理** | 所有环境变量在 `.env.example` 集中声明并在 README 说明；模型 API Key、限流阈值、预算阈值等均通过 env 配置，不硬编码 |
| **可观测性** | 结构化日志（Pino）输出到控制台，支持接入第三方日志平台（预留接口） |
| **兼容性** | 前端支持 Chrome、Safari、Edge 最新两个版本；响应式适配 1280px 以上桌面和 768px 以上平板 |

## 十一、风险与应对
| 风险 | 概率 | 应对措施 |
|------|------|---------|
| 模型 API 限流 | 中 | 启用故障转移，多模型轮询分摊压力 |
| 日消耗成本超预算 | 中 | V1 通过控制测试流量和模型额度降低风险；自动预算熔断与防刷机制列入后续待办 |
| 模型协议变更 | 低 | 适配器模式隔离变化，单个模型变更不影响全局 |
| 单机故障导致全站不可用 | 中 | V1 接受单机部署边界；备份 PostgreSQL 数据，Redis 仅保存可重建的限流与健康状态，保留 Docker Compose 快速重建能力 |
| Nginx 代理导致 SSE 缓冲或超时 | 中 | 对流式接口关闭代理缓冲与缓存，延长读取超时，并通过同域 `/api` 路径进行端到端流式测试 |
| 单机资源争用 | 中 | 为 Web、网关、PostgreSQL 和 Redis 设置资源限制、健康检查与日志轮转，重点监控内存和磁盘使用率 |
| 容器重启导致短时 502 | 中 | 配置容器 `restart` 策略、健康检查和启动依赖；Nginx 仅向健康的应用容器转发请求 |
| 管理后台越权或误删数据 | 中 | 管理 API 强制单管理员认证、表与字段白名单、修改/删除二次确认、后端事务和不可变操作审计；不提供任意 SQL |
| 面试官无法快速本地启动 | 中 | README 写明 `docker compose up -d` 一键启动，并提供线上链接 |

## 十三、后续待办事项（不纳入 V1 验收）

### 13.1 成本保护与异常流量防护

V1 以串通 Agent、文生图、Prompt 优化、监控与部署流程为主要目标，暂不实现完整的成本防刷体系。后续上线公开演示前，需要补充以下能力：

- 以人民币预估费用作为主要预算控制指标，Token 数仅用于监控和辅助告警
- 增加全站小时与每日调用成本硬顶，避免通过代理池绕过单 IP 限流后持续消耗额度
- 将普通登录用户体验额度与面试/管理员演示额度隔离，防止公开额度耗尽导致演示不可用
- 模型调用前通过 Redis 原子预占最坏情况下的预计费用，调用结束后按实际用量结算，避免并发请求穿透预算上限
- 对 Agent 模型调用和文生图分别设置调用次数、并发数、`max_tokens` 与生成数量上限
- 预算达到阈值后按阶段降级：优先关闭文生图，再停止普通用户真实调用，但保留站点页面和受保护演示能力
- 视部署条件增加验证码、WAF、设备指纹或供应商侧账户额度限制，IP 限流仅作为第一层基础防护

### 13.2 内容安全与合规（V2）

V1 暂不实现公开站点的完整内容审核能力；在正式面向不受控用户开放文生图或公开运营前，必须补充独立于模型厂商自带拦截的内容安全链路，不能把合规责任完全交给上游模型。

- 对 Agent、文生图和 Prompt 优化的用户输入执行前置审核，至少覆盖涉黄、涉政、暴力、违法犯罪、未成年人风险及其他需要拦截的类别
- 对文生图结果执行输出审核；审核通过前不直接向前端展示、提供下载或写入公开历史记录
- 统一定义审核结果：通过、拒绝、需人工/二次判断、审核服务异常，并为前端提供明确且不泄露敏感规则的提示
- 审核服务不可用时采用 fail-closed 策略：暂停文生图和高风险内容生成，不因审核故障放行请求
- 记录 requestId、审核结果、命中类别、处置动作、规则/模型版本和时间等审计元数据；控制原始 Prompt 与图片的留存范围和期限，避免日志成为敏感内容存储
- 对连续提交违规内容的用户、IP 或设备执行临时封禁、提高验证码强度或降低额度，不能只依赖单 IP 限流
- 明确上游模型安全策略、平台自有策略和人工复核的责任边界，供应商审核结果只能作为一层信号
- 增加隐私政策、内容使用提示、违规反馈/举报入口，以及审核拒绝和申诉所需的基础产品文案
- 为审核链路补充监控指标和测试样例：拦截率、误杀率、审核延迟、审核服务错误率及典型违规 Prompt 回归测试

### 13.3 异步队列与后台任务

V1 暂不使用 BullMQ，日志与计费明细由网关直接写入 PostgreSQL。后续出现以下明确需求时再评估引入 BullMQ 与独立 Worker：

- 调用量上升后，数据库写入明显影响流式请求收尾延迟
- 计费、通知或审计写入需要失败重试、延迟执行和死信处理
- 文生图任务需要由服务端统一轮询，而不是由前端驱动轮询
- 需要对大量后台任务进行削峰、并发控制和运行状态观测

引入队列时必须同时设计任务幂等键、重试上限、退避策略、死信处理和任务监控，避免只增加组件而没有可靠性闭环。

### 13.4 Prompt 日志的数据治理

V1 为方便联调和排查问题，会在 PostgreSQL 与 Pino 日志中保存完整 Prompt，暂不设置自动清理周期。后续正式开放给不受控用户前，需要补充：

- Prompt 脱敏、摘要或按环境关闭完整内容日志
- 数据保留期限与自动清理任务
- 数据库和日志平台的访问控制与操作审计
- Dashboard、错误响应和导出数据中的敏感字段过滤
- 用户隐私提示、数据删除机制及备份数据的同步清理策略

### 13.5 海外模型厂商扩展

V1 仅接入通义千问、智谱 GLM、DeepSeek 三家国内模型。国内模型链路稳定后，再逐步增加以下海外厂商：

- OpenAI
- Anthropic Claude
- Google Gemini

海外模型扩展需要满足以下要求：

- 对外继续使用稳定的平台模型别名，实际厂商 model id 通过配置映射，避免厂商模型升级导致 Web 和 SDK 改接口
- 每家厂商实现独立 Provider Adapter，统一消息格式、流式增量、usage、错误码、取消和健康状态
- 建立模型能力矩阵，明确各模型是否支持流式输出、图片、思考内容、工具调用和上下文长度
- 计费配置支持美元单价、人民币换算汇率、价格版本和缓存 Token 等不同计费口径
- 评估国内服务器访问海外 API 的网络稳定性、超时、支付、账号和合规限制
- 为新增 Adapter 增加协议转换、流式结束、usage、异常和取消测试，不因扩展厂商破坏现有国内模型链路

海外模型不纳入 V1 里程碑和验收标准。

### 13.6 管理员认证升级

V1 为快速跑通中后台流程，暂时写死管理员账号 `root`、密码 `123456`，不建立用户表、角色或权限模型。由于源码仓库和站点最终会公开，这组凭证不能用于正式公开环境，后续必须完成：

- 管理员用户名和密码哈希改为环境变量或安全的密钥存储，不在源码中保留明文密码
- 强制修改默认密码，并增加密码强度要求
- 增加登录失败次数限制、会话失效和密钥轮换机制
- 视使用范围增加双因素认证、登录 IP 白名单或云端身份代理
- 保留现有 HttpOnly Cookie、CSRF 校验和管理操作审计
# Agent 视频生成补充

用户可在 Composer 上方进入视频生成模式，通过自然语言或自然语言加单张首帧参考图生成视频。首发能力聚合百炼北京地域的可灵、HappyHorse、Vidu 与爱诗，默认 5 秒、720P、16:9、带音频；Thread 内复用同一视频模型，能力不足时由服务端自动切换且不暴露厂商细节。生成结果先保存在 Thread Sandbox，仅在保存或下载时持久化到私有 OSS，并进入“我的创作”。预览支持同源 Range 播放。

暂不提供视频编辑、转码、自动重试、用户模型选择、内容审核、成本硬顶或取消防刷。平台任务 15 分钟超时，用户停止后立即逻辑取消并允许下一 Run，已提交的厂商任务只做后台状态与费用对账。
